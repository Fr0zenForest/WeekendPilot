# 板载调试日志层 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给板载加 USB 串口调试日志：开机打完整自检（传感器探测/配置/各功能开关），运行时按低频（~5Hz）打一行紧凑状态（模式/姿态/链路/主舵量/传感器有效位/定高&配平状态），方便起不来或行为不对时定位。

**Architecture:** 格式化逻辑放 core（纯逻辑、零硬件依赖、PC 可单测）：一个 `StatusSnapshot` 值结构 + `formatStatusLine(snapshot, char* out, size_t cap)` 写进调用方缓冲（无堆、无 Arduino）。Controller 加几个只读 getter（activeMode/altHoldEngaged/autoTrimLearning）暴露内部状态。板载 main.cpp 用 `WP_DEBUG_LOG` 编译门控：开机扩展自检、loop 里降采样组装 snapshot 调 formatter + Serial.print。控制环逻辑零改动。

**Tech Stack:** C++17（core 纯逻辑，编译开 -Wall -Wextra -Werror），Unity 单测（core 格式化），ESP32 Arduino（板载，pio 编译检查）。

> WARNING 数据真实性声明（用户硬性要求）：
> - core 的 StatusSnapshot/formatStatusLine 为新代码，纯格式化逻辑 PC 单测可完整覆盖（给定 snapshot→断言输出字符串）。
> - 板载日志输出（Serial.print 实际行为、开机自检的真实传感器探测结果）**只能在实物 ESP32-S3 上观察**，本环节只做 pio 编译检查 + 给出预期输出样例，**未在实物验证**。
> - `WP_DEBUG_LOG` 默认开（开发期），正式飞行可 -DWP_DEBUG_LOG=0 关闭以省 CPU/串口带宽。
> - 全部新代码/未实测项带 WARNING 标注。

```cpp
#pragma once
#include <cstdint>
#include <cstddef>
#include "types.h"   // kNumServos

namespace wp {

// WARNING 新代码。调试状态快照（值类型，由板载每帧组装；core 不碰硬件）。
struct StatusSnapshot {
    uint32_t t_ms = 0;
    uint8_t mode = 0;            // FlightMode 值
    float roll_deg = 0, pitch_deg = 0, yaw_deg = 0;
    bool link_ok = false;
    bool imu_valid = false, baro_valid = false, mag_valid = false;
    bool althold_engaged = false;
    bool autotrim_learning = false;
    uint16_t servo[kNumServos] = {0};
    int8_t tier = 0;            // SensorTier 值
};

// 状态行缓冲上限（含结尾 NUL）。一行紧凑文本，够放所有字段。
constexpr size_t kStatusLineCap = 160;

// 把 snapshot 格式化成一行紧凑文本写进 out（snprintf 语义，必 NUL 收尾）。
// 返回 snprintf 返回值（欲写字符数，不含 NUL；>=cap 表示被截断）。
int formatStatusLine(const StatusSnapshot& s, char* out, size_t cap);

}  // namespace wp
```

- [ ] **Step 4: 写实现**

创建 `core/diag/status_line.cpp`：

```cpp
#include "diag/status_line.h"
#include <cstdio>

namespace wp {

namespace {
const char* modeName(uint8_t m) {
    switch (m) {
        case 0: return "OFF";
        case 1: return "ANGLE";
        case 2: return "RATE";
        default: return "?";
    }
}
}  // namespace

int formatStatusLine(const StatusSnapshot& s, char* out, size_t cap) {
    if (out == nullptr || cap == 0) return 0;
    // 一行紧凑格式：
    // [t] MODE r/p/y | LINK ok IMU1 BAR0 MAG1 T<tier> | AH AT | s0 s1 s2 s3
    return snprintf(out, cap,
        "[%lu] %s r%.0f p%.0f y%.0f | LINK%s IMU%d BAR%d MAG%d T%d | %s %s | %u %u %u %u",
        (unsigned long)s.t_ms, modeName(s.mode),
        (double)s.roll_deg, (double)s.pitch_deg, (double)s.yaw_deg,
        s.link_ok ? "ok" : "?", s.imu_valid ? 1 : 0, s.baro_valid ? 1 : 0,
        s.mag_valid ? 1 : 0, (int)s.tier,
        s.althold_engaged ? "AH" : "--", s.autotrim_learning ? "AT" : "--",
        (unsigned)s.servo[0], (unsigned)s.servo[1],
        (unsigned)s.servo[2], (unsigned)s.servo[3]);
}

}  // namespace wp
```

注：`LINK%s` 在 link_ok 时输出 "LINKok"，丢失时 "LINK?"——测试 strstr("LINK") 命中即可；"AH"/"AT" 仅在激活时出现（否则 "--"），测试相应分支用激活态。
